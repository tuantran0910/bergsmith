# Support matrix

Status values:

- **Planned:** in the MVP scope, not yet implemented.
- **Certified:** implemented and its acceptance tests pass.
- **Later:** after the MVP (milestone in brackets).
- **Unsupported:** rejected during preview with an explanation.

Certification is scoped to the tested backend or execution path. Native local
rewrite certification does not certify distributed publication or recovery.
Update a row only when its acceptance tests pass (see the project plan §5).

| Manifest rewrite | Implemented (BS-031.T3, ADR 0063): a coordinator-only job (`rewrite_manifests`) under `jobs:submit`, disabled unless `manifests.rewrite_enabled` is set. | Dangling-delete removal | Implemented (BS-031.T3, ADR 0063): a coordinator-only job (`remove_dangling_deletes`) under `jobs:submit`, disabled unless `deletes.dangling_removal_enabled` is set. | Storage breakdown | Implemented (BS-031.T4, proposed ADR 0064): separately bounded, opt-in table-prefix observations with live, retained, metadata, orphan-candidate and protected/other accounting; table and visible-table catalog pages. | Snapshot expiration | Implemented (BS-031.T1, ADR 0061): a metadata-only job publishes a standard `remove-snapshots` update under `jobs:submit`, keeping the current snapshot, every branch and tag, the table and connection retention bounds, and every snapshot pinned by a nonterminal job, expiration plan, or unresolved publication. Selection, planning, publication, ambiguous recovery, protected-snapshot replanning, and table-scoped pin serialization pass unit, PostgreSQL, and mock-catalog tests. Expiration is disabled unless `expiration.catalog_ref_safety` attests that the catalog atomically rejects removing a referenced snapshot |
| Orphan file cleanup | Implemented (BS-031.T2, ADR 0062): a coordinator-only job (`remove_orphan_files`) under `jobs:submit`, disabled unless `orphans.enabled` is set. It lists the table location, protects the metadata file and log, every snapshot-reachable file, statistics files, every manifest named by an unresolved publication intent, and Bergsmith's own trees, then deletes only objects older than the larger of `orphans.minimum_age_seconds` and the connection's execution plus unresolved-publication window. ## Authorization and identity

BS-023.T5 adds Users and Service identities pages, principal detail with scoped
grant creation and revocation, and Access on connection and table pages. The
pages follow the effective permission projection and use the existing API;
they add no authorization authority. Pool tokens are shown once in component
memory, and never stored in browser storage or query/mutation results. Browser
journeys cover provisioning, scoped grants, deactivation, one-time token display,
revocation, and narrow layouts under the coordinator CSP with axe in both themes.
Dialogs stay within short viewports and scroll internally; long principal names
wrap without widening confirmations. Browser regressions cover grant submission
at 390×320 and confirmation with a 200-character unbroken name.
