# UI revamp release notes (0.1.0)

The browser UI now follows the navigation and detail patterns in ADR 0056.
There is no API contract change; the coordinator, worker, and catalog behavior
are untouched by this release.

## Navigation and shell

- A grouped rail (Overview, Data, Operations, Administration) replaces the flat
  links; below 48rem it becomes a drawer that keeps the current destination
  visible.
- `/` is an overview that answers what needs attention: unresolved
  publications, failed or replanned jobs, health findings, schedule lag, and
  worker capacity, each gated by its own grant.
- Breadcrumbs, a labeled `main`, and a skip link make keyboard and screen
  reader navigation explicit. `+ New` offers only the creations the session may
  perform.
- Tables leads with `catalog.namespace.table` names; IDs, revisions, and raw
  states live behind technical details with copy actions.

## Lists and detail pages

- Lists share one table component with search, URL-addressable filters, sorting,
  cursor paging, and a phone-width card layout. Below 40rem the same rows render
  as cards and the filters open in a bottom drawer, so actions stay on screen at
  320 and 390 pixels.
- Table, job, catalog, and principal pages use addressable tabs. Catalog
  discovery sits at the top of its overview; access and settings appear only
  with their grants. An unknown tab falls back to the overview.
- The job page separates execution from publication, puts events first while a
  job runs and statistics first once it ends, and adds a Tasks tab. A failed job
  can be traced to a task and attempt, its failure reason and disposition, its
  duration, and its accepted outputs without leaving the page.
- Catalog settings show human durations next to the seconds the API stores. A
  save bar appears only while a form is dirty, offers an explicit discard, and
  keeps the draft when you switch tabs. A revision conflict still requires an
  explicit reload.
- Service-identity creation opens token management. A token is shown once; the
  Tokens tab unmounts when left, so the bearer does not remain on the page.

## Accessibility and performance

- Every browser journey runs axe in light and dark themes, plus a keyboard-only
  journey for the skip link, tab set, and a dialog's focus return.
- The first-load JavaScript is 80.7 kB gzipped, within the 175 kB budget; route
  chunks load on intent and the build now reports initial and lazy totals.
- Visual baselines for the catalog overview and settings compare in CI, and the
  browser gate uploads screenshots and traces on failure.

## Workflow changes

- Tab and filter state is part of the URL, so links open the same view.
- Access tabs require `grants:manage` at the connection, table, or organization
  scope. Workers-only operators see Tokens on a service identity, not an empty
  Access tab.
- Catalog routing and credential edits are still separate from settings, and an
  uncertain save still asks you to inspect the saved state before retrying.
- No catalog mutation is retried automatically.

## Known gaps

Deferred by decision, not regressions:

- Audit filtering by actor, action, resource, outcome, and date range, plus
  export and a detail drawer.
- A command palette and global search.
- A component gallery.
- Production catalog and storage certification, which belongs to the
  deployment acceptance run (BS-020.T4).
